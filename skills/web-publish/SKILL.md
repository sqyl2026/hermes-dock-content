# 公开网页与服务

目标是把用户的成果真正交付为可访问链接。容器里的 `localhost` 通常不能被用户直接访问；使用静态托管或出站隧道解决，不要停留在解释限制。

## 选择方案

| 场景 | 优先方案 |
|---|---|
| 中国大陆的临时网页、API 或动态服务 | cpolar；已有 NATAPP 配置时也可直接使用 |
| 中国大陆的静态网站或 SPA | EdgeOne Makers 中国站 |
| 海外或无账号临时预览 | Pinggy、Cloudflare Quick Tunnel、localhost.run |
| 已经使用 GitHub 的公开静态项目 | GitHub Pages |
| 长期动态服务 | 根据用户已有平台部署，或先用隧道交付预览链接 |

用户未说明地区时，面向企智盒的默认用户按中国大陆处理。大陆方案读取 [references/china-services.md](references/china-services.md)，海外方案读取 [references/overseas-services.md](references/overseas-services.md)。

方案不可用时主动尝试下一个合适方案。需要账号或 Token 时，不要让用户回到宿主机、编辑 `.env` 或操作命令行；直接在当前微信、企业微信、飞书或钉钉聊天中发送适合小白的申请步骤和官方链接。让用户申请完成后把 Token 发回当前聊天，收到后接手配置并继续发布。

## 执行流程

1. 找到要发布的构建产物目录或本地 HTTP 端口。静态项目优先使用 `dist/`、`build/`、`out/` 等生产产物。
2. 快速确认目标中没有 `.env`、私钥或明显的凭据文件，并确认没有把企智盒管理接口当作发布目标。
3. 启动或复用本地服务，用 `curl` 验证实际入口。静态目录可使用：

   ```bash
   python3 -m http.server 4173 \
     --bind 127.0.0.1 \
     --directory /opt/data/path/to/dist
   ```

4. 选择托管或隧道。优先复用已有客户端；需要安装免费客户端时，将明确版本放入 `/opt/data/.dock/web-publish-runtime/`，不要修改系统环境。
5. 使用 `process` 管理本地服务器和隧道，并把隧道输出同步写入当前 profile 的临时日志。需要等待 URL 时，使用 `scripts/wait_for_public_url.py` 轮询本地 API 和日志，不依赖一次 `process poll`。
6. 从当前仍在运行的隧道进程取得 URL，立即用它请求首页和一个关键资源或健康检查地址。若返回的是隧道错误页、旧页面或框架 Host 校验错误，修复后继续验证。
7. 交付 URL，并说明它是临时还是持续部署、何时会失效，以及如何停止。

不要仅因为容器没有入站端口就结束任务，也不要把隧道输出了 URL 当作已经成功。随机 URL 与产生它的进程绑定：不要为了切到后台而停止并重启隧道；进程退出或重连后，重新取得并验证新 URL。一个服务失败时，根据地区和内容类型换用其他方案继续。

## 必要约束

- 只发布用户要求的网页、构建目录或服务，不发布 profile 根目录、共享目录根目录、凭据文件或管理控制面。
- `9876`、`9877`、`9878`、`8642`、`9119` 以及 Docker socket 不作为发布目标。
- 可以接收用户在当前聊天发来的服务 Token。收到后不要在回复中完整复述，直接用于当前发布；通过技能脚本的标准输入传递，避免写进命令参数或项目文件。
- 只向用户索取完成发布所需的 Token，不索取网站账号密码、短信验证码或身份资料。
- 免费方案要求升级付费、绑定信用卡或选择长期域名时，再让用户决定。

这些约束不应扩大成繁琐审计。对普通静态构建产物做快速检查后直接发布；遇到可恢复错误就修复或切换方案。

## 完成交付

最终回复包含：

- 可点击的公网 URL；
- 已验证的页面或接口；
- 临时链接的失效条件，或静态托管的更新方式；
- 如果用户要求大陆访问，说明当前验证所使用的网络范围。

大陆多运营商可达性通常需要用户实际打开确认，但这不妨碍先交付已经验证的链接。用户要求停止临时分享时，终止隧道；只为本次分享启动的静态服务器也一并停止。
