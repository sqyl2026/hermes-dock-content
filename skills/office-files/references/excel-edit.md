# 修改现有 XLSX

用于修改已有工作簿的值、公式、样式、工作表或结构。先阅读 `excel-common.md`，并按任务记录必要基线。

## 选择写入路径

普通工作簿可以使用：

```python
workbook = openpyxl.load_workbook(INPUT_PATH, data_only=False)
```

出现以下情况时先调整写入方案或说明具体风险：

- 加载时警告图形、扩展、验证或其他对象将丢失；
- 用户要求修改 `.xlsm`；
- 用户要求“完全无损”但环境没有相应验证能力。

数据透视表、切片器、sparklines、外部连接、自定义 XML、嵌入对象、ActiveX 或数字签名需要针对性检查，但不因其存在就自动拒绝与其无关、可验证的修改。高层库无法完成局部任务时可以检查相关 OOXML；不要猜测性重写无关 part。

## 最小修改

- 通过工作表名和明确坐标定位；存在标签时同时核对标签。
- 只修改用户指定的单元格和属性。
- 修改值时保留未授权改变的公式、样式、数字格式、批注、超链接和数据验证。
- 修改文本不会自动变成公式；用户没有要求公式时防止公式注入。
- 修改样式时使用 `copy.copy()` 复制来源样式属性，不就地修改共享对象。
- 不用 `Workbook()` 重建现有工作簿。

## 行列和工作表结构

`insert_rows()`、`insert_cols()`、`delete_rows()` 和 `delete_cols()` 不会完整维护依赖。结构修改前检查：

- 同表和跨表公式；
- 合并区域；
- Excel Tables 和表格公式；
- 数据验证与条件格式范围；
- 命名区域和打印区域；
- 图表数据源；
- 冻结窗格、筛选和隐藏行列；
- shared formula、array formula 和动态数组。

没有实现所有受影响对象的级联更新时，不在复杂工作簿中插入或删除行列。可以改为在表尾追加数据，或先让用户确认接受结构变化。

重命名工作表时还要更新公式、命名区域、图表、数据验证和外部引用；无法完整更新时停止。

## 公式和缓存

涉及公式时读取 `excel-formulas.md`。始终用 `data_only=False` 编辑，保存后验证公式字符串。不要读取缓存值后把它写回公式单元格，也不要声称 openpyxl 已计算结果。

## 保存后

1. 保存到新的输出路径。
2. 重新打开并核对目标。
3. 比较工作表名称、顺序、可见状态、公式数量和相关高级对象基线。
4. 按任务比较表、合并区域、验证、条件格式、命名区域和高级对象。
5. 报告修改范围、未覆盖对象、公式缓存状态和视觉验证状态。
