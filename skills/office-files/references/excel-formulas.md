# Excel 公式与静态验证

用于写入、检查或修复公式。先阅读 `excel-common.md`；修改现有文件时同时读取 `excel-edit.md`。

## 写入公式

`openpyxl` 使用带前导 `=` 的公式字符串：

```python
worksheet["C2"] = "=A2+B2"
worksheet["D2"] = "=SUM(A2:C2)"
worksheet["E2"] = "='销售 数据'!B2"
```

- 文件内部函数名使用英文，参数使用逗号。
- 含空格、标点或中文歧义的工作表名使用单引号；名称中的单引号写成两个单引号。
- 根据业务需要选择相对、绝对或混合引用。
- 不把 Python 计算结果冒充为用户需要的可更新公式。
- 不为消除错误而默认包裹 `IFERROR()`；这会隐藏真实问题并可能改变结果类型。

## 特殊公式

修改 shared formula、array formula、data table formula 或动态数组前先读取底层 OOXML。没有实现主从范围、spill 范围和相关属性校验时，不把它们当普通单元格公式覆盖。

外部工作簿引用、DDE、WEBSERVICE 和其他联网公式不刷新。发现后报告，不自动访问目标。

## 缓存和计算

`openpyxl` 只保存公式，不计算。使用：

- `data_only=False` 查看和验证公式；
- `data_only=True` 只读取上次由兼容表格应用保存的缓存值。

缓存为空或过期不代表公式结果为零。绝不保存以 `data_only=True` 加载的工作簿。

## 静态验证

根据任务检查：

- 目标公式是否仍以 `=` 开头，函数名、分隔符和引用范围是否符合计划；
- 公式文本和命名区域中是否出现 `#REF!`；
- 被引用工作表是否存在，工作表名称大小写按 Excel 语义处理；
- 公式数量和复制范围是否符合预期；
- shared formula、array formula、data table formula 和动态数组结构是否仍完整；
- 外部工作簿、DDE 或联网公式是否保持未刷新状态。

静态检查不是完整公式解释器。它不证明：

- 公式业务逻辑正确；
- 所有 Excel 函数语法都正确；
- 运行时不会产生除零、类型或查找错误；
- LibreOffice/WPS 与 Excel 的计算结果完全一致；
- 简单的文本或正则检查识别了所有 3D、结构化、动态数组和外部引用语法。

静态验证无错误时只能报告“未发现可识别的阻断错误”。

## 动态重算

只有环境已经提供受支持的 Excel/WPS/LibreOffice 计算引擎时，才按任务需要对临时副本执行重算。不要为了验证临时安装办公套件，不用重算后的副本自动替换最终交付物；兼容引擎可能重新序列化格式或使用不同的函数实现。

没有计算引擎时明确报告动态验证未执行，并提示用户在 Excel/WPS 中打开、重新计算和保存。

## 修复公式

- 只修复能够从业务规则、相邻公式模式或用户说明中确定的错误。
- `#REF!` 需要确认正确来源范围，不能猜测。
- `#DIV/0!` 需要确认零分母的业务语义，不默认返回 `"-"`、零或空白。
- `#NAME?` 需要区分函数拼写、命名区域和版本不支持。
- 修复后比较公式数量、目标公式和引用范围，并重新静态验证。
