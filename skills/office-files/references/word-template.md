# Word 模板套用与多节结构

用于把内容套入 `.docx` 模板、迁移样式、填充带封面或占位符的模板，以及处理多节页眉页脚。先阅读 `../SKILL.md` 和 `word-common.md`；需要替换跨 run 占位符、保留审阅对象或修改复杂域时再读取 `word.md`。

## 模板任务分类

先判断模板属于哪一种：

- **纯样式模板**：主要提供字体、标题、段落、表格和页面样式，没有必须保留的封面、目录、分节或示例结构。使用样式映射方式，把已确认的模板样式应用到源文档。
- **结构模板**：包含封面、目录、固定章节、内容控件、占位符、多节、不同页眉页脚或页码体系。复制模板作为输出基底，再替换明确的占位内容。

模板同时包含样式和结构时按结构模板处理。不要先创建空白文档再凭观察重建复杂模板。

一个请求既要创建内容又要套模板时，先准备经过用户确认的内容结构，再填充模板；不要让排版步骤改变事实内容。

## 写入前分析

有源文档时同时分析源文档和模板；内容来自对话或其他格式时，分析模板并为待填内容建立对应清单。至少记录：

- 文件是否能被 `python-docx` 和 ZIP 读取；
- 段落、表格、图片、节、样式和编号数量；
- 标题层级、目录域、页码域和其他复杂域；
- 页眉页脚 part、首页/奇偶页设置及其 relationship；
- 超链接、书签、批注、修订、脚注、尾注和内容控件；
- 模板占位符、示例内容和固定内容；
- `styles.xml`、`numbering.xml`、theme、media 和相关 relationship；
- 源文档中不能安全迁移的文本框、公式、嵌入对象和未知扩展。

为内容建立明确映射，例如“源标题 → 模板标题占位符”“源第 2 节 → 模板正文区域”。占位符没有唯一命中、同一源内容映射到多个位置或模板固定内容与源内容冲突时，先询问，不猜测。

## 纯样式模板

按以下顺序执行：

1. 复制源文档到新的输出路径，以保留源文档的内容、关系和对象。
2. 建立源样式到模板样式的显式映射，不根据字体大小猜测标题级别。
3. 优先通过 `python-docx` 把已确认的字体和段落属性写入映射后的样式；页面属性按明确的节映射写入对应 `section` 或 `w:sectPr`。
4. 自定义标题样式同时设置正确的 outline level，确保目录和导航窗格可识别。
5. 只有用户要求“完全使用模板格式”时，才清理与目标样式冲突的直接格式；只删除已识别的格式属性。
6. 表格单独映射表格样式、单元格边距、表头和边框，不把正文段落规则机械套入单元格。
7. 保存后验证内容、关系和对象数量没有非预期变化。

页面设置按节处理。模板和源文档的节数或节用途不一致时，先建立“源节 → 输出节”的明确映射；无法唯一确定时先询问，不做全局覆盖。

不要直接用模板的整个 `styles.xml` 覆盖源文档。样式可能引用 `basedOn`、`next`、`link`、编号、theme 字体和 latent styles；未迁移依赖会产生断裂或外观漂移。

如果必须精确复制复杂样式定义，先解析依赖闭包，并同时迁移所需样式、编号和 theme 引用。没有实现依赖校验时停止，不做部分复制后声称套用成功。

## 结构模板

按以下顺序执行：

1. 拒绝已存在的输出路径。
2. 使用 `shutil.copy2()` 把模板复制为输出文件。
3. 打开输出副本，不修改原模板。
4. 按唯一占位符、书签、内容控件、表格坐标或明确章节锚点填充内容。
5. 保留模板的节、页眉页脚、目录、样式、编号、theme 和 package relationship。
6. 删除模板示例内容前确认它不是固定说明、法律条款、字段标签或页眉页脚内容。
7. 插入源内容时逐类处理段落、表格和图片，不把复杂 XML 节点从一个 package 直接挂入另一个 package。

普通文本占位符可能跨多个 run。遇到这类占位符时读取 `word.md`，使用可见字符映射定位和拆分边界，不通过 `paragraph.text = ...` 替换。

内容控件按结构区分：

- 普通主文档纯文本 `w:sdt`：先检查 `w:lock`；`contentLocked` 或 `sdtContentLocked` 时停止并报告，`sdtLocked` 只禁止删除控件且不妨碍填充内容。唯一定位后修改 `w:sdtContent`，保留 `w:sdtPr`、tag、alias、ID 和 `w:placeholder` 定义，并删除或设为 false 的 `w:showingPlcHdr`，避免新内容继续被 Word 视为占位文本。
- 数据绑定、重复节、嵌套或富内容 `w:sdt`：先检查 `w:dataBinding`、`customXml`、重复结构、内部对象及其 relationship；没有完整处理能力时停止。

文本框、公式、脚注、尾注和嵌入对象也不在 `python-docx` 的完整高层支持范围内。只有实现对应 part、relationship 和 ID 校验时才修改；否则报告未覆盖对象。

## 内容迁移和直接格式

模板样式会被源内容的直接格式覆盖。处理时区分：

- **内容语义**：文本、超链接、书签、域、脚注引用、批注范围、修订和图片关系；
- **段落语义**：样式、编号、缩进、对齐、分页控制和节属性；
- **字符外观**：字体、字号、颜色、粗斜体、下划线和高亮。

只在用户要求套用模板外观时移除冲突的字符外观和段落外观。保留内容语义及未指定属性。不要通过重建全部 run 或只保留纯文本来清理格式，这会丢失超链接、书签、域、修订和批注锚点。

源内容包含复杂对象时，优先：

1. 在输出模板中建立明确插入位置；
2. 为每种对象复制对应 part；
3. 生成新的 relationship ID、书签 ID、批注 ID、drawing ID 或编号 ID；
4. 重写新文档内的引用；
5. 验证不存在重复 ID 和悬空关系。

没有完成这些步骤时，不复制复杂对象。

## 多节、页眉和页脚

- 每一节的页面设置和页眉页脚引用由该节的 `w:sectPr` 决定。
- 中间节的 `w:sectPr` 位于该节最后一个段落的 `w:pPr`；最后一节的 `w:sectPr` 位于 `w:body` 末尾。
- `w:titlePg` 控制首页不同；奇偶页页眉页脚还依赖文档设置。不要只复制可见文字而遗漏设置。
- 页眉页脚可能链接到前一节。修改某节前确认是否共享同一个 part，避免一次修改影响多个节。
- 保留模板中不同节的页码格式、起始页码、方向、纸张、边距、分栏和垂直对齐。
- 单纯章节换页使用分页符；只有页面设置、页眉页脚或页码体系变化时才增加分节。
- 不用空段落模拟奇偶页、节间距或页面留白。

结构模板优先保留模板现有页眉页脚 part 和 relationship。不要根据截图重新创建复杂页眉页脚，也不要添加模板中不存在的边框、字号或装饰。

## 样式、编号和关系

样式迁移：

- 保持 `styleId` 唯一；
- 解析 `basedOn`、`next`、`link` 和编号依赖；
- 同名样式不等于同一 `styleId`，不要只按显示名覆盖；
- 自定义标题样式显式设置 outline level；
- 同时处理四个字体槽位和 theme 字体引用。

编号迁移：

- 同时迁移 `abstractNum` 和 `num`；
- 为输出文档分配未占用的 ID；
- 重写段落 `numId`；
- 保留级别、重启规则、缩进、编号格式和与样式的绑定；
- 没有迁移完整依赖时不声称列表格式已保留。

package relationship：

- 不复用来源文档中的 `rId`；
- 图片、超链接、页眉页脚、批注、脚注和嵌入对象分别检查 relationship；
- 外部链接和内部 part 使用不同 TargetMode；
- 删除内容后清理仅由本次删除产生的孤立关系，但不要清理无法确认用途的 part；
- 保存后检查所有内部 Target 存在，且重要 part 能从主文档或节属性到达。

## 验证门槛

套用模板后必须同时验证内容保留和模板结构。

| 范围 | 必查项 |
|---|---|
| 内容 | 标题、正文、表格内容、图片和用户指定字段完整，实际次数等于写入前显式映射中的计划次数 |
| 样式 | 样式映射、直接格式清理范围、outline level 和表格样式符合计划 |
| 结构 | 段落、表格、图片、节和占位符数量符合预期，没有意外空白内容 |
| 页眉页脚 | 各节引用、首页/奇偶页、链接到前一节和页码域保持正确 |
| 关系 | 图片、超链接、批注、脚注、页眉页脚等内部 Target 存在，无新悬空引用 |
| 审阅对象 | 原有修订、批注、书签和域未被意外接受、删除或压平 |
| 模板残留 | 示例姓名、演示数据、占位说明和未填字段已处理或明确报告 |

保存后重新打开输出，并对比写入前记录的源文档和模板基线。结构变化必须能对应到用户请求；无法解释的变化视为失败。

有兼容排版引擎时再逐页检查封面、目录、节切换、页眉页脚、页码、表格跨页和图片布局。没有排版引擎时明确说明只通过结构验证。

## 停止条件

出现以下情况时停止并报告，不做猜测性修复：

- 模板或源文档损坏、加密或依赖宏；
- 占位符或内容映射存在歧义；
- 需要迁移的复杂对象没有对应 relationship 和 ID 处理能力；
- 样式或编号依赖无法完整解析；
- 未知扩展、签名或自定义 XML 可能因保存受损；
- 保存后出现非预期内容丢失、对象数量变化、悬空关系或重复 ID；
- 用户要求精确复刻视觉效果，但环境没有可用排版引擎且模板结构不足以证明结果。
