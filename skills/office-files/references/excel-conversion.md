# CSV、TSV 与 XLSX 转换

用于 `.csv`、`.tsv` 和 `.xlsx` 之间的转换。先阅读 `excel-common.md`。

## 编码和分隔符

- 用户没有指定时，中文 CSV 输出使用 `utf-8-sig`。
- TSV 使用制表符并明确扩展名 `.tsv`。
- 输入编码不明确时先报告解码错误并让用户确认；不要静默轮流尝试多个编码。
- 分隔符不明确时检查样本并报告判断依据，不同时把逗号、分号和制表符当分隔符。

## XLSX 转 CSV/TSV

CSV/TSV 不保留：

- 多工作表结构；
- 样式、合并区域和列宽；
- 公式和公式缓存的双重语义；
- 图表、图片、数据验证和批注；
- 数据类型元数据。

每个工作表输出一个文件，并在写入前确定安全、唯一的文件名。先询问用户需要：

- 当前缓存显示值；
- 公式字符串；
- 还是两者分别输出。

公式缓存为空时不能写成零。大 XLSX 使用 `openpyxl(..., read_only=True)` 和标准库 `csv.writer` 流式导出，不使用 `pd.read_excel(..., sheet_name=None)` 一次载入全部工作表。

## CSV/TSV 转 XLSX

- 明确编码、分隔符、表头行和日期格式。
- 保留前导零的编号、邮编、身份证片段和产品编码为文本。
- 不把看似日期的普通编号自动转换为日期。
- 百分比和货币只有在语义明确时转换为数值并设置格式。
- 以 `=`, `+`, `-`, `@` 开头的不可信字段默认按文本写入；用户明确要求公式时才作为公式。
- 大文件使用 pandas chunks 或 openpyxl write-only 模式，并说明 write-only 模式的功能限制。

## 分阶段输出

多工作表或批量转换时：

1. 预先检查所有最终输出路径不存在。
2. 在最终输出目录内创建专用 staging 目录，确保 staging 与最终位置位于同一文件系统；不要从 `/opt/data/tmp` 跨 bind mount 假设 `rename()` 是原子的。
3. 验证所有文件非空、行数和列数符合计划。
4. 如果可以把整批结果交付为一个新目录，使用单次目录 `rename()` 发布，且目标目录必须不存在。
5. 如果结果必须作为多个文件直接放入已有目录，只能逐个提交：记录本次已创建的文件，失败时仅回滚这些文件，并明确这不是多文件事务。
6. 任一步失败时保留失败脚本和 staging 目录供排查，不删除或覆盖用户原有文件。

## 验证

- CSV/TSV 重新按明确编码和分隔符读取，核对行列数和关键值。
- XLSX 重新打开，核对工作表、行列数、关键值、数据类型和目标格式。
- 报告转换过程中必然丢失的样式、公式或高级对象。
